# 权限模型

默认拒绝，再按角色和路径白名单开放；本文件是策略设计，不能作为已生效证据。执行前须验证真实拒绝路径。

| 角色 | 允许读 | 允许写 | 工具 |
|---|---|---|---|
| planner | 需求、架构、基线选定文件 | 设计/测试提案 | 无shell、无外部MCP |
| test-author（实现前准备） | 批准候选接口与测试方案 | 指定测试目录及fixture | 不得写应用源码，不得改验收目标 |
| implementer（检查点1后） | 当前任务必要文档和源码 | 明确下发的模块/适配器范围 | read/edit；运行命令由编排器按固定清单执行 |
| verifier/reviewer | 代码、测试、脱敏输出 | 仅指定QA记录 | 不改源码、测试oracle或批准记录 |
| 应用AI角色 | 本run合资格证据、卡片和规则 | 结构化响应 | 只读行情/新闻工具；无审阅/发布/任意shell |
| 真实用户 | 审阅所需制品 | Human-only规则、真实批准 | 批准具体计划/测试/diff/产物hash |

所有agent禁止读仓库外凭据、私钥、浏览器数据、个人附件；禁止写`.opencode/rules.md`、真实批准、预算上限或权限策略。Codex可按用户明确授权操作仓库外课程凭据和API认证，但凭据不得传入开发上下文。

文件工具权限不等于OS沙箱。若允许shell，须另限制文件系统和网络；否则通过`cat`或脚本可绕过read规则。负面测试须覆盖absolute path、..、symlink、shell、MCP和provider切换。
